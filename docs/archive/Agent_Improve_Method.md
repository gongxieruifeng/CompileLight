### Agent优化：SKILL-DISCO 微软研究院
#### 定位目标：把 agent 执行轨迹“编译成可执行流程图 / 状态机”

SKILL-DISCO 利用大语言模型（LLM）作为编译器，把成百上千条历史成功日志（Traces）直接淬炼成一段段完美的、带分支循环的 **Python 真实可执行函数 [ 控制流子图(PFSM Subgraph)]**。

![](assets/17834910801216.jpg)


#### 第一阶段：自蒸馏（Distillation）

这个阶段的目标是：**把大堆不同任务、不同长度的流水账日志，提炼并归类成“带有参数和判断逻辑”的伪代码片段。**

#### 轨迹规范化（Trace Normalization）

**输入**：多条不同宇宙、不同物品的原始日志。
* *日志 1*：走到抽屉1 ➔ 打开 ➔ 没东西；走到抽屉2 ➔ 打开 ➔ 看到杯子 ➔ 拿起杯子。
* **日志 2**：走到书架1 ➔ 没东西；走到抽屉1 ➔ 打开 ➔ 看到钥匙 ➔ 拿走。
* **实现逻辑**：大模型架构师（Senior AI Systems Architect）出马，抹去具体的物体名字，换成变量（如 `drawer1` 变成变量 `l`），并**把隐藏在文字里的循环和判断逻辑用 Python 语法显式地写出来**。

**输出（中间程序）**：
```python
# 变成了一段带 while 循环和 if 条件的代码
while target_not_found:
    go_to(location)
    if "closed" in observation:
        open(location)

```

#### 子目标操作抽取 (Operation Extraction)
**实现逻辑**：一整条任务太长了（包含：找杯子 ➔ 洗杯子 ➔ 倒水）。如果把整条链当成一个技能，太死板无法复用；如果拆得太细（比如 `go_to` 算一个技能），又失去了封装的意义。

系统强制使用中等颗粒度（Subgoal-level）进行切分：将连续几步协同完成一个小目标的动作（步数 ``\ge 2``）切成一段段独立的“操作碎片（Operators）”。

#### 程序集整合与参数绑定 (Consolidation)
**实现逻辑**：宇宙 1 的 Agent 在厨房找杯子，开了 3 个抽屉；宇宙 2 的 Agent 在卧室找书，开了 4 个箱子。虽然它们去的地方不同、操作步数不同，但把具体名字抽掉换成参数变量后，它们在数学拓扑上对应的其实是**同一个带控制流的分支子图（PFSM Subgraph）**。

**结果**：系统把这些具有相同“参数化控制流结构”的碎片死死聚类（Cluster）到一起。只有那些得到了大量历史成功轨迹共同背书的工具池（高覆盖率），才会被批准晋级为“技能候选人”，并计算出一个重用率得分 ``r_k``。


#### 🖥️ 第二阶段：代码编译（Compilation）

通过第一阶段，我们手里只拿到了几段控制流的“设计图纸”。第二阶段的任务是把它们焊造成真正的工业级 Python 函数。

#### 技能规范化描述 (Skill Specification)

* 系统不急着写代码，先为这个高分群组建立严格的 **JSON 契约说明书（Specification）**。
* **声明内容**：规定好函数名（如 `search_object`）、输入参数类型（`locs: list, obj: str`）、前置条件（比如手必须是空的）、后置期望（必须拿到该物品）、以及它从刚才 ``r_k`` 继承来的置信度。

#### 代码合成与严苛验证 (Synthesis & Verification)

**代码合成**：大模型根据上一步的严密契约，正式手写出具备健全的 Bug 容错、异常处理和返回值协议的真实 Python 业务代码。

**held-out 验证（最核心的把关**：
* **考核指标 1**：运行时绝对不能报 Bug（Syntax/Runtime Error 必须为 0%）。
* **考核指标 2**：看它是不是真的帮 Agent **省下了做题的决策步数（Action Savings）**。
* **自愈**：如果执行失败，报错日志回传给大模型进行最多 ``R`` 次的在线打补丁和重调。如果 ``R`` 次后依然有 Bug，这个技能作为废品**直接丢弃**。

最终通过验证的，就是极其精简、健壮、能直接外挂给任何 Agent 大脑的商业级**标准技能库**。

#### 推理使用方案
当把 SKILL-DISCO 编译好的技能库（比如最后只凝聚出了 5 个通用大招）部署到真机上时：
系统直接把这 5 个函数的 API 说明书（JSON 契约）做成 Prompt 外挂塞给执行任务的小模型（哪怕是 Qwen-4B） 。
小模型在做题时，只要在 `<think>` 里发现眼前的困境符合说明书，它不需要自己一步步规划，直接在代码环境里输出一句：`call systematic_search_locations(all_drawers, 'book')` 。
